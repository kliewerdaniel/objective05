# Privacy Model

## Purpose

Define Objective's privacy model — data ownership, data retention, user control, and privacy guarantees for a local-first intelligence system.

## Scope

This document covers data ownership principles, data retention policies, user control mechanisms, privacy guarantees, and compliance considerations.

## Responsibilities

- Define data ownership and sovereignty principles
- Specify data retention and deletion policies
- Document user control mechanisms
- Define privacy guarantees
- Document compliance posture

## Assumptions

- Objective is a local-first system (see ADR-001)
- No data leaves the user's machine unless explicitly configured
- The user owns all data generated by the system
- Privacy is a fundamental design principle, not a compliance checkbox
- The user controls all aspects of data lifecycle

## Design

### Data Ownership Principles

**Principle 1: User Owns All Data**
All data stored by Objective is the user's property. This includes:
- Knowledge graph (entities, claims, events, narratives, contradictions)
- Raw source documents
- Generated broadcasts and audio
- Configuration and preferences
- Model files (subject to their original licenses)

**Principle 2: No Data Leaves Without Consent**
By default, Objective sends no data off the local machine:
- No telemetry (opt-in if enabled)
- No analytics
- No crash reports (handled locally)
- No usage statistics
- No "phone home" functionality
- Models are downloaded (inbound only) — no inference data is sent

**Principle 3: Data is Portable**
Users can export all their data in standard formats:
- Knowledge graph: JSON, CSV, RDF (Turtle)
- Documents: JSONL, raw files
- Broadcasts: Markdown, HTML, MP3
- Configuration: YAML

### Data Retention

**Default retention periods:**
```yaml
retention:
  raw_documents: 90 days      # Original fetched documents
  extraction_results: indefinite  # Entities, claims, relationships
  events: indefinite          # Formed events
  narratives: indefinite      # Formed narratives
  contradictions: indefinite   # Detected contradictions
  broadcasts: 90 days         # Generated broadcast text
  audio: 90 days              # Generated audio files
  audit_log: 90 days          # Audit trail entries
  logs: 30 days               # Debug logs
  snapshots:
    hot: 7 days               # Frequent snapshots
    cold: 30 days             # Daily snapshots
    archive: 90 days          # Weekly snapshots
```

**Per-source retention:**
```yaml
retention_per_source:
  rss: 30 days
  sec_filing: 365 days
  podcast_transcript: 180 days
  email: 90 days
  default: 90 days
```

**Data pruning:**
- Pruning runs daily (scheduled maintenance)
- User is notified before data is permanently deleted
- User can configure retention per data type
- "Keep forever" option available (user opt-in, with storage warning)

### User Control

**Data management UI:**

| Action | Location | Description |
|--------|----------|-------------|
| View all data | Knowledge graph explorer | Browse all entities, claims, events |
| Search data | Search bar | Full-text and semantic search |
| Delete single item | Context menu (right-click) | Delete entity, claim, event, document |
| Bulk delete | Settings > Data Management | Delete by type, date range, source |
| Export data | Settings > Data Export | Export in multiple formats |
| Import data | Settings > Data Import | Import entities, documents |
| Clear all data | Settings > Danger Zone | Factory reset with confirmation |
| Manage retention | Settings > Data Retention | Configure retention periods |

**Deletion semantics:**
- Soft delete: mark as `valid_to = now` (preserves history, excludes from queries)
- Hard delete: physically remove from database (irreversible)
- Default: soft delete with 30-day permanent deletion window
- Hard delete available in "Danger Zone" with confirmation

**Export formats:**

| Data | Formats | Schema |
|------|---------|--------|
| Entities | JSON, CSV | `{id, name, type, aliases, confidence}` |
| Claims | JSON, CSV | `{id, subject, predicate, object, confidence, source}` |
| Events | JSON, CSV | `{id, title, type, importance, start_time, end_time}` |
| Narratives | JSON, CSV | `{id, title, strength, event_count}` |
| Contradictions | JSON | `{id, type, severity, claims, resolution}` |
| Full graph | RDF/Turtle | Standard RDF triples |
| Documents | JSONL | Raw document format |
| Broadcasts | MD, HTML, MP3 | Rendered formats |
| All data | JSON archive | Complete system export (excluding models) |

### Privacy Guarantees

**Guarantee 1: No External Communication**
Objective does not initiate communication with any external server except:
- Source servers configured by the user (for fetching content)
- Model repositories (for downloading models at user request)
- Update servers (for checking updates at user request, can be disabled)

**Guarantee 2: No Telemetry by Default**
Telemetry is:
- Not collected
- Not transmitted
- Not stored
- Fully disabled unless user explicitly opts in

If the user opts in to telemetry:
```yaml
telemetry:
  enabled: false
  data_collected:
    - "version"
    - "os_type"
    - "uptime"
    - "anonymous_performance_metrics"
    - "feature_usage_counts (no content)"
  data_not_collected:
    - source content
    - extracted entities
    - claims, events, narratives
    - user configuration
    - source credentials
    - any personal data
  opt_in_prompt: "Would you like to help improve Objective by sharing anonymous usage statistics? No content data is ever collected."
```

**Guarantee 3: No Third-Party Data Access**
- Source credentials are stored locally with OS-level encryption
- No data is shared with third parties
- No advertising or tracking infrastructure
- No embedded analytics (no Google Analytics, no Mixpanel, etc.)

**Guarantee 4: User Controls Delete**
- Any data point can be deleted by the user
- Deletion removes the data from all storage subsystems
- Audit log preserves deletion record (not deleted content)
- Complete data deletion available ("Delete all data")

### Compliance Considerations

While Objective is a personal system and not subject to organizational compliance requirements, the architecture supports:

| Regulation | Requirement | How Objective Meets It |
|-----------|-------------|----------------------|
| GDPR Art. 17 (Right to Erasure) | User can delete their data | Soft + hard delete; full data clear |
| GDPR Art. 20 (Right to Portability) | User can export their data | JSON, CSV, RDF export |
| GDPR Art. 15 (Right of Access) | User knows what data is stored | Full data browser in UI |
| CCPA (Right to Delete) | User can request deletion | Clear all data function |
| Data minimization | Only necessary data collected | No telemetry; no unnecessary data |

### Privacy Considerations for Specific Features

**Content ingestion:**
- Source content is fetched over HTTPS (encrypted in transit)
- Source content is stored locally (encrypted at rest if configured)
- User controls which sources are configured
- Source credentials are encrypted at rest

**Model inference:**
- All inference runs locally — no data sent to model APIs
- Model context windows are ephemeral (not persisted after inference)
- Prompt data is not logged (DEBUG level may log prompts if explicitly enabled)

**Broadcast:**
- Generated broadcasts are stored locally
- Audio files are stored locally
- No cloud distribution (user may choose to export and share)

### Privacy Defaults Checklist

| Feature | Default | Can User Change? |
|---------|---------|------------------|
| Telemetry | Disabled | Yes (opt-in) |
| Crash reporting | Disabled (local only) | Yes (can enable external) |
| Usage analytics | Disabled | Yes (opt-in) |
| Log level | INFO | Yes |
| Data retention | 90 days | Yes (per type) |
| Network exposure | localhost only | Yes (can enable remote) |
| TLS for remote access | Disabled (no remote by default) | Yes (user configures) |
| Credential encryption | OS keyring | Yes (file fallback) |
| Plugin network access | Blocked | Yes (per plugin) |

## Failure Modes

| Failure | Impact | Mitigation |
|--------|--------|------------|
| User expects more privacy than configured | Data exposure | Clear privacy defaults; configuration review during setup |
| Data retention not enforced | Storage growth | Automatic pruning; monitoring alerts |
| Export fails (large dataset) | Data stuck in system | Streaming export; chunked export |
| User deletes data accidentally | Permanent data loss | Soft delete with recovery window; confirmation dialogs |
| Plugin exfiltrates data | Privacy violation | Plugin sandbox; network restrictions; no direct graph access |
| Logs contain personal data | Log data contains PII | Log scrubbing; log access restricted to user |
