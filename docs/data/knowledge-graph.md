# Knowledge Graph

## Purpose

Define the complete data model for Objective's knowledge graph, including entities, claims, events, narratives, contradictions, and sources. This document serves as the canonical schema reference for all graph operations.

## Scope

This document covers the graph schema, node types, edge types, properties, constraints, indexes, and query patterns. It does not cover storage implementation (see `storage-architecture.md`) or provenance tracking (see `provenance-model.md`).

## Responsibilities

- Define the authoritative graph schema
- Specify all node and edge types with properties
- Define constraints and indexes
- Document query patterns for common operations
- Provide migration guidelines for schema changes

## Assumptions

- Kuzu DB is the graph database (see ADR-002)
- Schema is enforced at the application layer (Kuzu has limited schema enforcement)
- All nodes and edges carry temporal and provenance metadata
- IDs are UUID v7 (time-sortable UUIDs) generated by the creating service

### Node Types

#### 1. Source Node

Represents an information source (RSS feed, Reddit subreddit, YouTube channel, etc.)

```cypher
CREATE NODE TABLE Source (
    id              STRING      PRIMARY KEY,  -- UUID v7
    source_type     STRING      NOT NULL,      -- rss, reddit, youtube, podcast, pdf, blog, sec, govt
    name            STRING      NOT NULL,      -- Human-readable name
    url             STRING      NOT NULL,      -- Base URL or identifier
    description     STRING,                   -- Optional description
    language        STRING      DEFAULT 'en',
    active          BOOLEAN     DEFAULT true,
    poll_interval   INT32,                    -- Minutes between polls
    last_polled_at  TIMESTAMP,
    error_count     INT32       DEFAULT 0,
    confidence      FLOAT       DEFAULT 1.0,  -- Source reliability (0-1)
    -- Temporal fields
    created_at      TIMESTAMP   NOT NULL,
    updated_at      TIMESTAMP   NOT NULL,
    valid_from      TIMESTAMP   NOT NULL,
    valid_to        TIMESTAMP,                 -- NULL = current
    metadata        JSON                       -- Source-specific metadata
)
```

#### 2. Document Node

Represents a single fetched document (article, post, video transcript, PDF)

```cypher
CREATE NODE TABLE Document (
    id              STRING      PRIMARY KEY,  -- UUID v7
    source_id       STRING      NOT NULL,      -- FK to Source
    external_id     STRING,                    -- ID from source system
    url             STRING      NOT NULL,      -- Canonical URL
    title           STRING,                    -- May be empty
    author          STRING,
    published_at    TIMESTAMP,
    fetched_at      TIMESTAMP   NOT NULL,
    content_hash    STRING      NOT NULL,      -- SHA-256 of body for dedup
    language        STRING      DEFAULT 'en',
    word_count      INT32,
    -- Temporal fields
    created_at      TIMESTAMP   NOT NULL,
    updated_at      TIMESTAMP   NOT NULL,
    valid_from      TIMESTAMP   NOT NULL,
    valid_to        TIMESTAMP,
    metadata        JSON                       -- Document-specific metadata
)
```

#### 3. Entity Node

Represents a real-world entity (person, organization, location, concept, event)

```cypher
CREATE NODE TABLE Entity (
    id              STRING      PRIMARY KEY,  -- UUID v7
    entity_type     STRING      NOT NULL,      -- Person, Organization, Location, Concept, Event_Topic
    canonical_name  STRING      NOT NULL,      -- Preferred display name
    aliases         STRING[],                  -- Alternative names
    description     STRING,                    -- Brief description
    entity_metadata JSON,                     -- Type-specific metadata
    confidence      FLOAT       DEFAULT 0.5,  -- Aggregate confidence (0-1)
    mention_count   INT32       DEFAULT 1,    -- Times mentioned across documents
    -- Temporal fields
    created_at      TIMESTAMP   NOT NULL,
    updated_at      TIMESTAMP   NOT NULL,
    valid_from      TIMESTAMP   NOT NULL,
    valid_to        TIMESTAMP,
    provenance      JSON                       -- Source attribution list
)
```

Entity types and their metadata:

| Type | Metadata Fields |
|------|----------------|
| Person | `occupation`, `nationality`, `birth_date`, `death_date`, `aliases` |
| Organization | `industry`, `headquarters`, `founded`, `parent` |
| Location | `country`, `coordinates`, `population`, `type` (city/country/region) |
| Concept | `domain`, `keywords`, `related_concepts` |
| Event_Topic | `temporal_span`, `location`, `participants` |

#### 4. Claim Node

Represents a factual statement extracted from a document

```cypher
CREATE NODE TABLE Claim (
    id              STRING      PRIMARY KEY,  -- UUID v7
    claim_text      STRING      NOT NULL,      -- The extracted statement
    subject_id      STRING      NOT NULL,      -- FK to Entity (subject)
    predicate       STRING      NOT NULL,      -- Relationship predicate
    object_id       STRING,                    -- FK to Entity (object, optional for attributive claims)
    object_value    STRING,                    -- Literal value if not an entity
    claim_type      STRING      NOT NULL,      -- attribution, relation, attribution, quantification, temporal
    sentiment       FLOAT,                     -- -1.0 to 1.0
    confidence      FLOAT       DEFAULT 0.5,  -- Extraction confidence (0-1)
    evidence        STRING,                    -- Supporting text excerpt
    -- Temporal fields
    created_at      TIMESTAMP   NOT NULL,
    updated_at      TIMESTAMP   NOT NULL,
    valid_from      TIMESTAMP   NOT NULL,
    valid_to        TIMESTAMP,
    provenance      JSON                       -- Source document list
)
```

#### 5. Event Node

Represents a real-world event formed by grouping related claims

```cypher
CREATE NODE TABLE Event (
    id              STRING      PRIMARY KEY,  -- UUID v7
    title           STRING      NOT NULL,      -- Generated title
    description     STRING,                    -- Detailed description
    event_type      STRING      NOT NULL,      -- political, business, disaster, science, sports, etc.
    status          STRING      DEFAULT 'active', -- active, evolving, resolved, archived
    importance      FLOAT       DEFAULT 0.5,  -- Computed importance score (0-1)
    confidence      FLOAT       DEFAULT 0.5,  -- Aggregate confidence (0-1)
    start_time      TIMESTAMP,                 -- Event start (if temporal)
    end_time        TIMESTAMP,                 -- Event end (if known)
    location        STRING,                    -- Primary location
    participating_entities STRING[],           -- Entity IDs
    claim_count     INT32       DEFAULT 0,
    source_diversity FLOAT     DEFAULT 0.0,   -- 0-1, how many independent sources
    -- Temporal fields
    created_at      TIMESTAMP   NOT NULL,
    updated_at      TIMESTAMP   NOT NULL,
    valid_from      TIMESTAMP   NOT NULL,
    valid_to        TIMESTAMP,
    provenance      JSON
)
```

#### 6. Narrative Node

Represents a narrative — a cluster of related events forming a coherent story

```cypher
CREATE NODE TABLE Narrative (
    id              STRING      PRIMARY KEY,  -- UUID v7
    title           STRING      NOT NULL,      -- Generated title
    summary         STRING,                    -- Concise narrative summary
    narrative_type  STRING      NOT NULL,      -- ongoing, developing, resolved, recurring
    status          STRING      DEFAULT 'forming', -- forming, active, mature, declining, archived
    strength        FLOAT       DEFAULT 0.0,  -- Composite strength score (0-1)
    confidence      FLOAT       DEFAULT 0.5,
    coverage_score  FLOAT       DEFAULT 0.0,  -- How comprehensively covered (0-1)
    diversity_score FLOAT       DEFAULT 0.0,  -- Source diversity within narrative
    recency_score   FLOAT       DEFAULT 0.0,  -- How recent the latest event is
    event_count     INT32       DEFAULT 0,
    source_count    INT32       DEFAULT 0,
    -- Temporal fields
    created_at      TIMESTAMP   NOT NULL,
    updated_at      TIMESTAMP   NOT NULL,
    valid_from      TIMESTAMP   NOT NULL,
    valid_to        TIMESTAMP,
    provenance      JSON
)
```

#### 7. Contradiction Node

Represents a detected contradiction between two or more claims

```cypher
CREATE NODE TABLE Contradiction (
    id              STRING      PRIMARY KEY,  -- UUID v7
    contradiction_type STRING   NOT NULL,      -- direct, implied, temporal, factual_error
    description     STRING      NOT NULL,      -- Description of the contradiction
    severity        FLOAT       DEFAULT 0.5,  -- How significant (0-1)
    confidence      FLOAT       DEFAULT 0.5,  -- Detection confidence (0-1)
    resolution_status STRING    DEFAULT 'unresolved', -- unresolved, resolved, false_contradiction
    resolution      STRING,                    -- Resolution explanation if resolved
    -- Temporal fields
    created_at      TIMESTAMP   NOT NULL,
    updated_at      TIMESTAMP   NOT NULL,
    valid_from      TIMESTAMP   NOT NULL,
    valid_to        TIMESTAMP,
    provenance      JSON
)
```

### Edge Types

#### 1. DOCUMENT_BELONGS_TO (Document → Source)

```cypher
CREATE REL TABLE DOCUMENT_BELONGS_TO (
    FROM Document TO Source,
    fetched_at TIMESTAMP NOT NULL,
    confidence FLOAT DEFAULT 1.0
)
```

#### 2. EXTRACTED_FROM (Entity → Document, Claim → Document)

```cypher
CREATE REL TABLE EXTRACTED_FROM (
    FROM Entity TO Document,
    relevance   FLOAT DEFAULT 0.5,  -- How relevant entity is to document
    position    INT32[],            -- Character offsets in document
    confidence  FLOAT DEFAULT 0.5
)

CREATE REL TABLE CLAIM_EXTRACTED_FROM (
    FROM Claim TO Document,
    position    INT32[],            -- Character offsets
    confidence  FLOAT DEFAULT 0.5
)
```

#### 3. ENTITY_MENTIONED_IN (Claim → Entity)

Links the claim to the entities it references.

```cypher
CREATE REL TABLE ENTITY_MENTIONED_IN (
    FROM Claim TO Entity,
    role        STRING,             -- subject, object, context
    confidence  FLOAT DEFAULT 0.5
)
```

#### 4. CLAIM_SUPPORTS_EVENT (Claim → Event)

```cypher
CREATE REL TABLE CLAIM_SUPPORTS_EVENT (
    FROM Claim TO Event,
    relevance   FLOAT DEFAULT 0.5,
    confidence  FLOAT DEFAULT 0.5
)
```

#### 5. EVENT_BELONGS_TO (Event → Narrative)

```cypher
CREATE REL TABLE EVENT_BELONGS_TO (
    FROM Event TO Narrative,
    relevance   FLOAT DEFAULT 0.5,
    sequence    INT32               -- Order within narrative
)
```

#### 6. NARRATIVE_RELATED_TO (Narrative → Narrative)

```cypher
CREATE REL TABLE NARRATIVE_RELATED_TO (
    FROM Narrative TO Narrative,
    relationship_type STRING,       -- parent, sibling, fork, merge
    strength    FLOAT DEFAULT 0.5
)
```

#### 7. CONTRADICTION_INVOLVES (Contradiction → Claim)

```cypher
CREATE REL TABLE CONTRADICTION_INVOLVES (
    FROM Contradiction TO Claim,
    role        STRING,             -- claim_a, claim_b
    confidence  FLOAT DEFAULT 0.5
)
```

#### 8. ENTITY_RELATED_TO (Entity → Entity)

Direct relationship between entities (e.g., "works_for", "located_in")

```cypher
CREATE REL TABLE ENTITY_RELATED_TO (
    FROM Entity TO Entity,
    relationship_type STRING NOT NULL,  -- works_for, located_in, part_of, founded_by, etc.
    confidence  FLOAT DEFAULT 0.5,
    evidence    STRING,
    valid_from  TIMESTAMP NOT NULL,
    valid_to    TIMESTAMP
)
```

### Query Patterns

#### Find all entities mentioned in a document

```cypher
MATCH (d:Document {id: $docId})<-[e:EXTRACTED_FROM]-(entity:Entity)
RETURN entity.canonical_name, entity.entity_type, e.confidence
ORDER BY e.confidence DESC
```

#### Find all claims about an entity

```cypher
MATCH (e:Entity {id: $entityId})<-[m:ENTITY_MENTIONED_IN]-(c:Claim)
WHERE c.valid_to IS NULL
RETURN c.claim_text, c.confidence, c.created_at
ORDER BY c.created_at DESC
```

#### Find active events with supporting claims

```cypher
MATCH (ev:Event {status: 'active'})
WHERE ev.valid_to IS NULL
OPTIONAL MATCH (c:Claim)-[s:CLAIM_SUPPORTS_EVENT]->(ev)
RETURN ev.title, ev.importance, ev.confidence, ev.start_time,
       count(c) as claim_count
ORDER BY ev.importance DESC
```

#### Find all narratives containing an entity

```cypher
MATCH (e:Entity {id: $entityId})
MATCH (e)<-[:ENTITY_MENTIONED_IN]-(c:Claim)-[:CLAIM_SUPPORTS_EVENT]->(ev:Event)-[:EVENT_BELONGS_TO]->(n:Narrative)
WHERE n.valid_to IS NULL AND n.status IN ['forming', 'active', 'mature']
RETURN DISTINCT n.id, n.title, n.strength, n.status
ORDER BY n.strength DESC
```

#### Find unresolved contradictions involving high-confidence claims

```cypher
MATCH (c:Contradiction {resolution_status: 'unresolved'})
WHERE c.valid_to IS NULL AND c.confidence > 0.7
MATCH (c)-[:CONTRADICTION_INVOLVES]->(cl:Claim)
WHERE cl.valid_to IS NULL
RETURN c.description, c.severity, collect(cl.claim_text) as conflicting_claims
ORDER BY c.severity DESC
```

#### Temporal query: what did we know about entity X in date range

```cypher
MATCH (e:Entity {id: $entityId})
MATCH (e)<-[m:ENTITY_MENTIONED_IN]-(c:Claim)
WHERE c.valid_from >= $startDate
  AND (c.valid_to IS NULL OR c.valid_to <= $endDate)
RETURN c.claim_text, c.confidence, c.created_at, c.valid_to IS NULL as is_current
ORDER BY c.created_at DESC
```

### Schema Migration

Schema changes follow this process:

1. New schema version defined in `schema/v{N}.json`
2. Migration script created with verifiable before/after queries
3. System starts in read-only mode during migration
4. Migration executed in a transaction
5. System resumes normal operation
6. Rollback script available for 7 days

**Backward-compatible changes** (no migration needed):
- Adding optional properties to nodes
- Adding new node types
- Adding new edge types

**Breaking changes** (migration required):
- Removing properties
- Changing property types
- Removing node or edge types
- Renaming properties

## Failure Modes

| Failure | Impact | Mitigation |
|---------|--------|------------|
| Schema drift | Write failures, query errors | Schema version tracked in graph, validated on write |
| Missing indexes | Slow queries | Query performance monitoring, index coverage report |
| Orphaned edges | Query correctness issues | Referential integrity enforced at application layer |
| Migration failure | System unavailable | Rollback script, backup before migration |
| Deadlock | Transaction failure | Kuzu retry logic, timeout configuration |
